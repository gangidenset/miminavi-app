# ミミナビ（Android 最小版）

「耳だけで、迷わないスマートナビゲーション」の最小ゴール版です。

- Android アプリとして起動する
- iPhone の Beacon Simulator が送る iBeacon を受信する
- 事業所（福岡支店 4F）の図面を持ち、図面の B-01〜B-13 に置いた iPhone から現在地を推定する
- 行き先（会議室・受付・給湯室・トイレなど 12 か所）を声か文字で伝えると、ルートを計算して音声で案内する

画面のデザインはデモ（ミミナビ.html）に合わせています。

## 構成

| 場所 | 内容 |
|---|---|
| `map/floor.drawio` | **フロアマップ（draw.io）**。図面を変えるときはこれを編集する |
| `tools/analyze_rssi.py` | 測定結果 CSV から距離の式の値（A・n）と、体の向き・壁などによる RSSI のずれを求める分析ツール |
| `tools/drawio_to_map.py` | draw.io → アプリ用地図データ（`map.js`）の変換ツール。ビルド時に自動で実行 |
| `app/src/main/assets/map.js` | 変換後の地図データ（自動生成。直接編集しない） |
| `app/src/main/assets/index.html` `app.css` `app.js` | 画面・位置推定・ルート探索・音声案内 |
| `app/src/main/java/jp/miminavi/app/MainActivity.java` | 画面（WebView）と端末機能の窓口。権限、読み上げ、音声認識、方位センサー、CSV の書き出し |
| `app/src/main/java/jp/miminavi/app/BeaconScanner.java` | BLE スキャン。RSSI を直近4秒で平均し、0.5秒ごとに画面へ渡す |
| `app/src/main/java/jp/miminavi/app/BeaconParser.java` | 広告パケットの解析（iBeacon / AltBeacon / Eddystone-UID） |

外部ライブラリは使っていません（Android Gradle Plugin 9.4.1 / Gradle 9.6.0 / Java のみ）。

## iPhone（Beacon Simulator）の設定

- 形式：iBeacon
- UUID：全台同じ値（例：E2C56DB5-DFFB-48D2-B060-D0F5A71096E0）
- Major：全台 1
- **Minor：図面の B-xx の番号に合わせる**（B-01 の場所に置く iPhone は Minor 1、B-13 は Minor 13）
- iPhone は画面をつけたまま、アプリを前面に表示しておく（画面が消えると送信が止まります）
- 自分の iPhone だけを拾うには、「ビーコン」タブで受信中のビーコンの「このUUIDを使う」を押すか、UUID を入力して追加する（複数登録可。登録外の UUID のビーコンは一覧にも位置の計算にも使わず、Android の OS 側でも絞り込む。新しい UUID を追加するときは「他のUUIDも表示する（追加用）」で一時的に表示できる）

図面には置き場所の候補を5か所（B-01 トイレ前、B-02 入口、B-03 受付前の交差点、B-04 会議室（8）、B-05 事務所前）用意しています。手元の2台で試す場合は、案内したいルートの両端に近い2か所を選びます（例：会議室（8）なら B-03＋B-04、事務所なら B-03＋B-05、トイレなら B-01＋B-03）。

実際に置いた場所が図面の B-xx の位置と違うときは、「図面」タブの一覧で B-xx の「動かす」を押し、図面上で置いた場所をタップすると、名前（B-xx）はそのままで位置だけ変えられます（現在地の計算・案内・測定の実際の距離のすべてに使う。端末に保存され、「元に戻す」で図面の位置に戻る。元の位置は図面に点線の丸で表示）。

アプリは Minor 番号で図面のビーコンに自動で対応させます。番号が合わない場合は、「ビーコン」タブの各ビーコンにある「図面の位置」で B-xx を選ぶか、「図面をタップして場所を指定…」で好きな場所に置けます（手動の設定が優先。端末に保存されます）。

## 使い方

1. 「ビーコン」タブ：受信中の iPhone と、対応する B-xx・RSSI・推定距離を表示。iPhone から 1m 離れて「1mで補正」を押すと距離の精度が上がります
2. 「図面」タブ：推定した現在地（オレンジの点）、各ビーコンの受信状況、目的地を表示
3. 「案内」タブ →「この施設で案内を始める」→ 方角合わせ → 行き先を話す（または行き先ボタンを押す）
   - 「トイレ」のように候補が複数あるときは「男子トイレと女子トイレ、どちらですか？」と聞き返します
   - 曲がり角の手前・曲がるとき・ドアの手前・目的地の手前で読み上げます
   - 目的地から約 1.2m 以内（または目的地そばのビーコンに約 1m 以内）で「到着しました」
   - 現在地が分からないときや「デモ歩行」を押したときは、ルートを自動で歩く想定で進みます

`app/src/main/assets/index.html` は PC のブラウザでも開けます（受付付近に立っている想定の疑似ビーコンで動作）。

## 測定の記録と書き出し（ビーコンタブ）

RSSI・推定距離の測定（測定手順書・測定結果一覧の Excel）に使う機能です。

1. 「ビーコン」タブの「測定の記録」で、対象のビーコン・実際の距離・設置場所・高さ・向き・障害物を入れる（入力は次回も残る）
   - iPhone を何台も並べて一度に測るときは、対象を「受信中のすべて」にする。受信中のビーコンごとに設定欄が出るので、iPhone ごとの実際の距離・向き・高さ・設置場所を入れる（空欄は共通の値を使う）
   - ビーコンごとの「図面で置く」で、iPhone を実際に置いた場所を図面上で指定できる（B-xx は名前のまま位置だけ変わる。図面にない Minor のビーコンは P-xx として置く。「元に戻す」で図面の位置に戻る）
   - 「回数」を3回・5回にすると、同じ条件で5秒おきに続けて記録する（測定回は 1、2、3… と自動で付く。待ち時間中も「中止」で止められる）
   - 複数のビーコンを同時に測るとき（例：B-01・B-02 に iPhone、B-03 にミミナビ）は、対象を「受信中のすべて」にし、「ミミナビの位置」で B-03 を選ぶ（図面をタップして任意の地点も指定できる）。各ビーコンまでの実際の距離は図面から自動で計算し（両方の高さを入れれば高さの差も含む）、推定位置のずれも記録する
2. 「記録を始める」を押す。30／45／60 秒のあいだ、0.5 秒ごとに次を保存して自動で終わる（記録中は減衰係数 n を変更できない）
   - RSSI（アプリが距離に使う直近4秒の平均）、最新の受信値、推定距離、1m 地点の値（標準か補正か）、推定位置、測位方式
3. 「結果を書き出す（CSV）」：1回の記録×ビーコンごとに1行。列の順番は測定結果一覧（Excel）と同じなので、そのまま貼り付けられる
   - RSSI・推定距離の最小・平均・最大、測定回（同じ条件で何回目か）、距離誤差・絶対誤差・誤差率、生の受信値の最小・平均・最大、受信回数、端末、アプリ版
   - 「ミミナビの位置」を指定した場合は、その位置・推定位置の平均・位置のずれ（表示位置／案内ルートに寄せる前の計算位置）も
4. 「生データを書き出す（CSV）」：0.5 秒ごとの全記録（あとで集計し直すとき用）

書き出し先は Android の保存画面で選べます（端末の「ダウンロード」や Google ドライブなど）。CSV は Excel で文字化けしないよう BOM 付き UTF-8 です。記録は端末に保存され、「記録をすべて消す」か各記録の「消す」を押すまで残ります。

## 測定データの分析（距離の式の値を決める）

1. 測定の記録で、実際の距離・向き・**体の向き**（ビーコンに対して 正面／右向き／左向き／背中）・障害物（壁越しは「壁」）を入れて記録する
   - 距離データ：体 正面・障害物 無しで、0.5／1／2／3／5／7／10m など距離を変えて測る（各距離で 3〜5 回）
   - 体の向き：同じ距離（例 1m・3m・5m）で、体の向きだけを変えて測る
   - 壁越し：同じ距離で、壁のあり・なしを両方測る（壁ありだけだと距離のせいか壁のせいか区別できない）
   - 高さ：実際に使うときと同じにする（例 iPhone はデスクの上 0.7m、ミミナビは手に持って 1.4m）。「実際の距離」には床の上の（水平の）距離を入れ、iPhone と Android の高さを両方入れる。分析ツールが斜めの距離に直して計算する
2. 「結果を書き出す（CSV）」で書き出した CSV を分析する（何個でも。同じ記録は1回だけ数える）

```
python3 tools/analyze_rssi.py 測定結果1.csv 測定結果2.csv --out 分析結果.md
```

距離の式 RSSI = A − 10·n·log10(d) に最小二乗で当てはめ、次を出します。

- 基準条件（体 正面・縦・障害物なし）での A と n
- 体の向き・スマホの向き・障害物ごとの RSSI のずれ（dB）と、補正しないと距離を何倍に見積もるか
- ビーコン（iPhone）ごとのずれ
- 今のアプリの値（A=−45, n=4.0）・当てはめた値・ずれの補正込みで、推定距離の誤差を比べた表

## フロアマップの更新方法

1. `map/floor.drawio` を draw.io（https://app.diagrams.net）で開いて編集する
2. GitHub のリポジトリで `map/floor.drawio` を上書きアップロードする（Add file → Upload files）
3. 自動でビルドが走り、数分後に APK が新しい地図で更新される

draw.io 側のルール（図形を選んで Ctrl+M の「データを編集」で設定）

| kind | 意味 | 補足 |
|---|---|---|
| `wall` / `glass` / `partition` | 壁（線） | 通れない |
| `door` / `opening` | ドア・開口（壁の隙間に置く四角） | 通れる。`access=staff` で関係者用ドア |
| `furniture` / `pillar` / `equipment` | 家具・柱・設備 | 通れない |
| `room` | 部屋・エリア | 名前の表示と建物の内側の判定に使う |
| `destination` | 目的地 | `label` が名前、`keywords` が呼び方（カンマ区切り） |
| `beacon` | ビーコン | `label` が B-xx、`minor` が iPhone の Minor |
| `corridor`（または赤い四角） | 案内ルート | ルートはここを優先して通り、現在地もここに寄せる |
| 「イス」レイヤーの図形 | イス | デスクに収納する前提で通れる扱い |

- 縮尺：`length_mm` を設定した壁（西の外壁 7,694mm・南の外壁 16,478mm）から、縦横それぞれ自動で補正します
- 手元で変換を確認する場合：`python3 tools/drawio_to_map.py map/floor.drawio app/src/main/assets/map.js`

## 位置推定とルートのしくみ（PoC 用の簡易版）

- 距離 d = 10^((A − 受信RSSI) ÷ (10 × n))。A は1m地点の強さ（「1mで補正」の値、なければ −45dBm）、n は減衰係数（初期値 4.0、ビーコンタブで調整）
- 現在地の求め方は、ビーコンタブの「現在地の求め方」で選ぶ（標準は近接型）
- **近接型**（標準）：距離は使わず、強さの順番と差だけを使う。狭い部屋や反射の多い所では RSSI が距離で素直に変わらず（実測で 1m→4m でも約9dB しか下がらない）、推定距離から計算すると大きくずれるため
  - 1m地点の値で補正した強さ（受信RSSI − A）で、いちばん強い2台を選ぶ
  - 2台それぞれの案内ルート上でいちばん近い点を、案内ルートに沿って結ぶ
  - 2台の強さの差 Δ から、強い方から見て全体の f = 1 ÷ (1 + 10^(Δ ÷ 15)) の所にいるとする（差 0dB で真ん中、差 15dB で強い方から1割の所。15 は実測の当てはめ n≈1.5 の 10×n）。1台だけならそのビーコンのそば
  - **ビーコンの真横に引っ張る**：いちばん強いビーコンが1m地点の強さ（「1mで補正」の値、なければ実測の平均 −55dBm）から 3dB 以内で、2番目より 3dB 以上強い状態が2回（約1秒）続いたら、そのビーコンの真横にいるとして位置をそのビーコンの点にする。1m地点から 5dB 以上弱くなるか、2番目との差が 1dB を切るまで続ける（すぐに出入りしないよう、やめる条件はゆるい）。図面タブの使用ビーコンに「近接型（B-03 のそば）」と出る
  - ビーコンは、曲がり角・ドアの前・目的地の前など読み上げる地点の、案内ルートから見通せる所に、ルートに沿って4〜6m 間隔で置くとよい
- **距離から計算**：受信台数で測位方式を切り替える
  - 1台：1点測位（ビーコンを中心に半径 d の円の上で、前回の位置の方向にある点）
  - 2台：2点測位（歩ける場所のうち、2台までの距離が推定距離にいちばん合う所。2台を結ぶ線の外側（ビーコン・ビーコン・自分の並び）も求められる。同じくらい合う所が複数あれば、案内ルート・前回の位置に近い所。2台だけでは線の左右の区別はつかないので、配置は3台が三角形に見えるようにするのがよい）
  - 3台以上：近い3台で3点測位（円の式を引き算した連立方程式を解く。3台が一直線に近いときは最小二乗）
- 高さの補正：ビーコンタブの「ビーコンの高さ」「スマホを持つ高さ」を両方入れると、推定距離（空間の斜めの距離）から高さの差を除いた床の上の距離 √(d² − 高さの差²) で現在地を求める（空欄なら補正しない）。測定の記録中は、記録の条件の高さ（ビーコンごとの iPhone の高さ・Android の高さ）を使う。測定の記録の推定距離・誤差は、これまでどおり空間の距離で比べる
- 求めた位置は前回となめらかにつなぎ、案内ルート（案内中はそのルート）の上に寄せて表示する
- 今いる部屋は、部屋ごとのいちばん強いビーコンで判定（到着の判定に使う）
- 図面を 0.2m のマスに分け、案内ルートを優先し、曲がる回数の少ないルートを計算（ダイクストラ法）

## Android Studio で動かす場合

社内ネットワークでは SSL 検査の影響で Gradle がビルドに必要な部品を取得できないため、上記の GitHub Actions でのビルドを使ってください。社外ネットワークなどで Android Studio を使う場合は、このフォルダを「Open」で開いて ▶ で実行できます。

## 既知の制約

- 案内中はアプリを前面に表示したまま使う前提です（画面消灯中のスキャンは未対応）
- 音声認識は端末の音声入力（Google など）を呼び出します。入っていない端末では行き先ボタンか文字入力を使ってください
- 読み上げは端末の日本語音声を使います
